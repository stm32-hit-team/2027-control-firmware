# 2027 工创赛 RFID 电动车固件

这是根据去年 STM32F103 工程重新编写的 PlatformIO 版本。RFID 与 TTS
模块按“型号、协议和接法与去年相同”处理；没有读取或修改正在设计的
`今年的工程.eprj2`。

## 工作原理

1. STM32 通过 USART1 周期发送寻卡命令。
2. 检测到卡后保存 4 字节 UID，并读取数据块 4、5、6、8；块 7 是扇区控制块，
   因此跳过。
3. 数据按 GB2312 校验，以 `0x00` 或 `0xFF` 作为结束/填充标志。
4. 完整文字按显式长度送入 TTS 队列，再通过 USART2 原样发送给 TTS。
5. TTS 合成语音，STM32 本身不保存录音，也不根据 UID 查硬编码地点名。
6. 同一张卡持续停留时只触发一次；连续三次确认无卡后，同卡可以再次触发；
   不同 UID 即使文字相同也分别播报。
7. TTS 使用 8 条静态消息队列；若队列暂时满，RFID 状态机会保留当前卡片内容并
   重试投递，成功后才把该 UID 标记为已处理，避免静默漏播。

## 默认引脚和串口

| 功能 | STM32F103 引脚 | 默认参数 |
| --- | --- | --- |
| RFID TX/RX | PA9 / PA10，USART1 | 9600, 8N1 |
| TTS TX/RX | PA2 / PA3，USART2 | 9600, 8N1 |
| 比赛红灯 | PC13 | 低电平点亮，识别后亮 500 ms |
| 电机 PWM | PA0 / PA1，TIM2 CH1/CH2 | 默认不启用 |
| 调试/下载 | PA13 / PA14 | SWDIO / SWCLK |

RFID 默认保持 9600，不在上电时盲切 115200。去年代码的切换流程没有确认 ACK，
模块掉电复位后可能与主控永久失联。9600 对当前 4 块、64 字节以内文本足够；若实车
测速证明不足，再依据该模块手册增加带 ACK 的波特率切换。

## PlatformIO 使用

在 macOS 终端进入本目录：

```sh
pio run -e stm32f103c6
pio run -e stm32f103c8
pio run -e stm32f103c6_motor_check
pio run -e stm32f103c6 -t upload
```

默认目标是去年 IOC 声明的 `STM32F103C6T6`（32 KB Flash、10 KB RAM）。如果新板
最终确定为 C8，使用 `stm32f103c8` 环境，不要只改链接脚本或伪装内存容量。
`stm32f103c6_motor_check` 只用于确认默认关闭的电机代码仍能编译，不应在电路真值表
确认前直接下载到车上。

## macOS 主机测试

协议、状态机和 TTS 队列不依赖 HAL，可直接运行：

```sh
sh scripts/run_host_tests.sh
```

测试由 Apple Clang 编译，并开启 AddressSanitizer 和 UndefinedBehaviorSanitizer。
覆盖旧协议黄金向量、校验和、0x7F 转义、坏帧恢复、响应长度校验、多块读取、
同卡驻留去重、离场重置、不同 UID 同文本、队列满重试和 TTS 显式长度发送。

## 可调参数

统一在 `include/app_config.h` 修改。默认 `APP_ENABLE_MOTOR=0`，因为目前只确认 RFID
和 TTS 与去年一致，电机驱动真值表及当前电路尚未确认。改为 `1` 后会恢复旧工程的
PA0/PA1 PWM2 逻辑、3 秒晚启动、1 秒缓启动和定时停止；第一次上电必须架空车轮，
确认“停止/正转”电平后再落地测试。

## 卡片数据约定

- 文字使用 GB2312，可混合可打印 ASCII。
- 从物理块 4 开始写；推荐在文本结尾写 `0x00`，其余字节清零。
- 需要跨扇区时使用 4、5、6、8，不能把文字写入块 7。
- 当前最大播报文本为 64 字节。
- 卡片存文字，不存音频；不要在程序中写死比赛地点名称。

## 仍需实物验证

- RFID 模块响应帧字段、卡类型和 4 字节 UID 与去年模块完全一致。
- TTS 对 GB2312、`<S>3` 以及最大 64 字节文本的实际支持。
- 车辆经过标签时的读取窗口、天线方向和轮询间隔。
- 电源跌落和电机启动干扰下，USART1/USART2 是否丢帧或复位。
- 新电路 MCU 型号、电机驱动真值表、唯一红灯引脚和下载接口。
